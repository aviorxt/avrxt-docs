# Editorial standard

This is documentation for avrxt’s personal website, not a commercial platform.

Every guide needs a unique descriptive title, a useful summary, a clear purpose, actionable instructions, interpretation of results, limitations, troubleshooting, and related reading where relevant. Extend a page only when new material answers a real reader question.

Use repository code for implementation claims and official provider documentation for changing product behavior, pricing, limits, and security instructions. Record a review date for time-sensitive guides. Do not invent personal anecdotes, usage statistics, testimonials, deployment dates, or search-ranking promises.

Keep historical article context separate from current instructions. Never include credentials, private administration URLs, subscriber information, or real confirmation tokens in examples. Prefer example.com and clearly marked placeholders.

Before release, run `npm run check` and `npm run links`, inspect desktop and narrow-screen previews, and verify migration redirects. Owner approval is required before pushing or publishing this prepared work.
