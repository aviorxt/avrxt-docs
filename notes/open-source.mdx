Choose a project because it solves a specific problem. This directory links to the upstream repositories rather than repackaged downloads or popularity rankings. It is a reading and evaluation list, not an endorsement of every plugin or hosted service associated with a project.

## Evaluate beyond the README

Check the license for the specific component and release you intend to use. Read installation instructions, supported runtimes, release activity, security reporting guidance, and contribution rules. Open source does not necessarily mean every hosted feature or enterprise integration is free. Avoid copying an installation command from an unrelated tutorial when upstream instructions are available.

## Try one real workflow

For an API change, sketch the request flow, save a sanitized request, inspect its JSON, and add a browser test only where browser behavior matters. Each tool should remove friction. If a workflow is already simple and reliable, adding another dependency may not improve it.

Keep private tokens out of request collections, exported diagrams, test recordings, and logs. Secret-scanner findings need review; a clean scan is not proof that a repository contains no sensitive material. If a real credential has been exposed, revoke or rotate it before treating history cleanup as the solution.

## Contribute responsibly

Start with a reproducible bug report, documentation correction, or small test. Read the project’s contribution policy before opening a large change. See [first contributions](/notes/contributing) and [bug reports](/notes/bug-reports).
