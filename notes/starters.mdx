## Personal-site starter

Extract the archive and open `index.html` in a browser. It needs no package installation or build step. Replace the example name, description, links, and footer before publishing. The CSS uses system fonts and a dark layout without external assets. Inspect the source and test keyboard navigation and narrow-screen layout after your edits.

The template has no working contact form or newsletter backend. An example contact link uses a placeholder domain. Add only integrations you understand, then follow the [hosting guide](/technical/static-hosting). A template is a starting point, not an accessibility certification.

## Developer recipes

Use Node 22 or newer. From the extracted directory, run:

```sh
node --test
```

There are no third-party dependencies. The tests cover pagination boundaries, cache expiry and capacity, and local limiter behavior. Read the source before adapting it. The [pagination guide](/notes/recipe-pagination) and [cache guide](/notes/recipe-cache) explain the contracts.

## Important scope limits

The cache and limiter are in-memory and process-local. They reset on restart and do not coordinate across server instances. Entry count is bounded, but stored value bytes are not. They are not a production distributed cache or complete abuse-prevention system. The upload helper is a browser size hint, not server validation or content scanning.

Before release, add the authorization, persistence, error policy, observability, and security review required by your actual application. Keep the original license notice when reusing the examples. Check the [learning paths](/notes/learning-paths) if you want a sequence rather than an isolated snippet.
